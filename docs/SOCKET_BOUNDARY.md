# Socket event and acknowledgement boundary

The original Node API supports optional acknowledgements on `conversation.subscribe(matchId, callback)` and `message.send({conversationId,text,clientMessageId}, callback)`. Extra client event data can occupy that callback position. Both success and error paths now invoke it only when it is a function. A missing, null or non-function callback is treated as absent; a valid authorized message can still persist without an acknowledgement, as before.

Acknowledgement payloads remain compatible: subscription success is `{ok:true}`, message success is `{data:savedMessage}`, subscription failure is `{error:"Conversation unavailable"}`, and message failure is `{error:"Message could not be sent"}`. Existing UUID/text/object validators, authentication, active-match checks and sender admission remain authoritative. Malformed event shapes return the same generic errors when a callback is present, without exposing validator/database details or persisting invalid messages.

Acknowledgement delivery errors are contained. They do not reject an unobserved async event listener or turn an already persisted message into a second error acknowledgement. Clients that cannot confirm persistence retry with the same `clientMessageId`; the existing send service returns the saved row rather than inserting another one. This is not exactly-once network delivery or a new delivery receipt feature.

Five focused tests use real Socket.IO polling connections. Two safely await the actual registered handlers to reproduce the previous `TypeError: ack is not a function` without deliberately crashing a test process. Live-wire cases cover non-function callback positions, normal no-ack sends, stable-ID replay, malformed inputs and unchanged acknowledgement payloads. A callback-delivery failure case confirms neither listener rejects after a persistence/validation outcome.

Five additional tests use real WebSocket connections to verify established-session expiry/revocation, logout across tabs sharing a session, blocking across four participant tabs, and reconnect catch-up after offline persistence. An independent authorized session continues receiving messages when another session expires or logs out. Blocked participants and outsiders cannot subscribe, send or read history. The reconnect test combines sequence-based REST catch-up with a live socket tail and checks saved IDs and sequences for gaps or duplicates. These are automated protocol tests; they do not establish durable event envelopes or multi-instance delivery.

No schema migration, hosted Worker/UI change, acknowledgement status-code expansion or protocol envelope version is introduced. The hosted prototype continues to use its separate authorized HTTP polling path.
