## Release gates

1. Finish missing P0 behaviors above and execute every master-prompt acceptance scenario; no P1 expansion is required for this increment.
2. Run the authored browser suite against a fresh database, review 360px layout and all focus/error states, and measure contrast, overflow, and keyboard accessibility.
3. Configure real Sandbox merchant/buyer credentials through secrets settings, perform two actual approved captures and a cancellation/refund, and verify webhook reachability/signatures. Mock tests do not satisfy this gate.
4. Add content moderation, email/object storage, enforce service/retention policies and distributed rate limits, complete privacy/security review.
5. Validate provider permissions, merchant fit, terms/cancellation support, backup/restore, human moderation, observability and financial incident response before any live deployment.

No live mode, payout, escrow, wallet, stored balance, subscriptions, or real merchant booking is implemented. P1/P2 remain deferred. Working name does not imply PayPal affiliation or trademark clearance.

## Payment lifecycle refinements

The Node API now preserves completed/pending refund state and expiry across cancellation retries, and rechecks consent expiry when a provider capture completes. A delayed second capture expires the plan and queues both payments for compensation instead of confirming it. Five dedicated PostgreSQL/mock-provider regressions cover these cases and authoritative late-capture recovery. Full distributed worker leases, partial refunds and real Sandbox evidence remain outstanding in #7/#8. The hosted mock adapter is separate and unchanged by this fix.

## Discovery, response-contract and Postman refinements

Exact discovery retries now respect changed visibility/preferences without returning stale closed match IDs; established paused chat remains governed separately. Proposal and owner financial snapshots project only catalogue/receipt fields, removing derived planning-window bounds and unknown legacy JSON; interactive suggestion bounds remain intentionally available for selecting a valid date. The core/taste Postman collections are exported and executed with isolated fixtures; guarded manual Sandbox artifacts are documented but unexecuted. See `DECISION_REPLAY.md`, `RESPONSE_PRIVACY.md` and `../postman/README.md`. These bounded fixes do not complete signed discovery pagination, API-wide contracts or real provider validation.

## Auth, date and worker concurrency refinements

Challenge issuance/completion now serializes on stable account rows and rechecks eligibility, preventing duplicate first tokens and resets/confirmation after suspension/deletion. Ended/elapsed plans reject preference/proposal/suggestion work; completed paid dates cannot be cancelled into refunds. Outbox generations fence stale cancellation results from overwriting newly queued capture compensation, with verified refund evidence required for settlement. Migration003 must precede updated original API/worker startup; local development/test databases were migrated. Broader durable auth abuse controls, full date availability/timezone handling and distributed worker leases/retries remain open. Hosted runtime code is unchanged.

## Availability windows and provider-evidence refinements

Date suggestions now use only the remaining overlap and exclude experiences whose full duration no longer fits. Early capture notifications stay durable with scheduled correlation/evidence retries, due-work ordering and bounded quarantine rather than being silently processed. Completed Sandbox refund evidence uses exact canonical USD strings; integer-based formatting avoids float rounding/coercion. Migration004 adds webhook retry metadata and must precede updated original API/worker startup; applied locally. Quarantined/unsupported notifications require review, not an assumption that no funds moved. These changes do not complete native Sandbox evidence, all webhook families, distributed leases or date timezone/accessibility work.
